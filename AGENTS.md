# AGENTS.md

Rules for everyone who changes this repo, humans and AI agents alike. If something here conflicts with habit, this file wins.

## The project
Tau (τ) is a 3D website where a user travels to a real, measured black hole and sees how much they age versus how much time passes on Earth. It is also the reproducible basis for a paper. Read first:
- [docs/architecture.md](docs/architecture.md): monorepo layout and layers
- [docs/physics.md](docs/physics.md): equations and assumptions
- [docs/traceability.md](docs/traceability.md): on-screen element → equation → code → reference
- [docs/adr/](docs/adr/): architecture decisions

## Golden rules
1. **Traceability (RULE #1).** Anything that represents physics (a number, color, brightness, position, motion or sound) must come from an equation or from data with a source. Tag the producing code with `@trace T-xx`, and give it a row in `docs/traceability.md`. If no equation produces an effect, it does not go in the scene. Decorative UI motion is allowed only if it cannot be mistaken for physics. When the physics or data fall short, say so on screen instead of inventing.
2. **Python is the source of truth** (`backend/src/tau/physics/`). The TS mirror (`frontend/src/physics/`) holds only per-frame code and must pass the golden tests generated by Python.
3. **Layers only point inward** (ADR-0001). CI enforces it, so don't silence the linters.
4. **Data:** no numbers from memory. Every value carries a DOI/arXiv reference, and unknown values are `null`. Never modify `data/raw/`.
5. **Reproducibility:** fixed random seeds. Generated artifacts are committed and must be regenerated whenever their inputs change.
6. **UI palette is chrome only.** It must never tint the 3D scene (see `frontend/src/ui/styles/tokens.css`).

## Documentation duty: every change is recorded
| You changed… | You must also update… |
|---|---|
| Anything user-visible or behavioral (code, data, config) | `CHANGELOG.md` under `## [Unreleased]` (Added / Changed / Fixed / Removed). CI fails otherwise, unless the PR has the `no-changelog` label (only for pure refactors, tests or tooling with no visible effect). |
| An equation, constant or physical assumption | `docs/physics.md` and `docs/traceability.md` |
| A physical element of the scene | `docs/traceability.md` (row + status `planned`/`implemented`) and `@trace` in code |
| Catalog or star data | `docs/data-sources.md` and the reference inside the data file |
| **Architecture**: a new layer, module boundary, dependency direction, new service, major dependency, data flow or deploy model | A **new ADR** `docs/adr/NNNN-short-title.md` (Status, Date, Context, Decision, Consequences), plus `docs/architecture.md`. If it replaces an older ADR, set the old one to `Status: superseded by ADR-NNNN`. Never edit an accepted ADR's decision; write a new one. |
| Setup, commands or conventions | `README.md` and/or this file |

## Conventions
- **Language:** English everywhere: code, comments, docstrings, docs, commits, PRs, issues and UI text.
- **Branches:** `type/short-kebab-description` off `main`, where type is one of `feat`, `fix`, `docs`, `chore`, `refactor`, `test`, `ci`, `perf`. Example: `feat/hyperbolic-travel`.
- **Commits:** [Conventional Commits](https://www.conventionalcommits.org/):
  - Format: `type(scope): imperative summary` (≤ 72 chars, no period).
  - Types: `feat`, `fix`, `docs`, `refactor`, `test`, `perf`, `chore`, `ci`, `build`.
  - Scopes: `physics`, `catalog`, `pipeline`, `api`, `sim`, `scene`, `ui`, `app`, `data`, `docs`, `ci`, `backend`, `frontend`.
  - Keep commits small and atomic: one logical change, with tests passing at every commit.
  - Breaking changes use `!` (`feat(api)!: …`) and a `BREAKING CHANGE:` footer.
- **Pull requests:**
  - One concern per PR. The title follows Conventional Commits, because it becomes the squash commit.
  - Fill in the template checklist. CI must be green before merging, and merges are squash only.
  - Never commit directly to `main`.
- **Versioning:** SemVer tags `vX.Y.Z`. When releasing, move `[Unreleased]` entries into a `## [X.Y.Z] - YYYY-MM-DD` section. Paper releases get a Zenodo DOI.

## Code style
- SI units, with the unit in the name: `r_m`, `mass_kg`, `tau_s`.
- Every physics function has a docstring that cites the equation and its reference.
- Pure functions in `physics`, and no speculative abstractions.
- Tests: `backend/tests/` (pytest) and `*.test.ts` next to the code (Vitest). New physics needs limit tests (e.g. r → ∞ gives factor → 1) and published reference values.

## Checks (same as CI)
```bash
cd backend
uv run ruff check && uv run ruff format --check
uv run mypy && uv run lint-imports && uv run pytest
uv run python -m tau.tools.check_trace
uv run python -m tau.api.openapi && git diff --exit-code   # contract up to date

cd ../frontend
npm run lint && npm run format:check && npm run typecheck && npm test && npm run build
```
Run them before saying something is done.
